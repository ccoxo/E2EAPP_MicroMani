# 机械寻零与参考点返回：逐轴版本审阅说明

日期：2026-09-22。状态：代码、离线验证和候选构建完成；尚未部署、未做本版本实机运动验收。

## 使用方式

设置页的运动控制卡保留工作原点相关功能，增加独立的机械参考点区域。

| 入口 | 行为 |
| --- | --- |
| 回工作原点 | 沿用现有实验工作原点用途 |
| 返回机械参考点 | 只返回所选轴已确认的参考脉冲，不运行硬件寻零、不更新参考 |
| 机械寻零 | 只对所选轴执行硬件寻零，确认完成且反馈新鲜、停稳后更新参考 |

两个机械入口均默认不选轴，可全选 X/Y/Z/Roll/Pitch/Yaw，也可选择任意子集。先选轴，再审阅动作，最后确认执行。维护寻零明确提示旋转轴可能沿固定方向转较大角度，不能保证最短路径。当前所选多轴仍采用已有 HAL 执行方式，不代表具备避碰规划。

每个轴显示“已确认”或“待确认”。任一所选返回轴待确认时，整个返回请求被拒绝；未选轴不会被附带启动。寻零、返回分别显示执行中、完成或失败，急停后的迟到成功应答不能显示完成。

## 参考记录规则

- 新增 `homeReference.leftAxisConfirmed` / `rightAxisConfirmed`，按硬件侧的 X/Y/Z/Roll/Pitch/Yaw 顺序保存六个布尔值。界面按操作者侧显示，操作者左仍对应硬件右。
- 旧脉冲值保留。缺少显式逐轴确认记录时全部视为待确认，不从旧整侧 valid 标记推断寻零成功，也不从旧日志自动导入本机标定。
- 开始寻零前先持久化撤销所选轴的确认。全部所选轴完成、停稳且读取新鲜反馈后才确认这些轴并更新脉冲；失败、断连或中断不写成功位置，所选轴保持待确认。
- 未参与轴的参考、工作原点位置和模拟遥测偏移保持不变。参与轴的工作原点仍按现有参考偏移逻辑维护，并经过有效限位检查。
- 普通设置保存、旧快照不能伪造或恢复确认；改变某轴参考脉冲会撤销该轴确认。前端读取寻零结果只同步显示，不再次通过设置保存把旧状态写回。
- 旧 `valid/leftValid/rightValid` 为兼容既有偏移及限位计算而保留，不能作为“全部完成机械寻零”的证明；机械参考点返回权限仅认逐轴确认。

“已确认”表示软件观察到成功寻零，并不等于绝对编码器校验，也不独立证明与历史熟悉姿态一致。此版本未新增控制器掉电、计数重置后的基准识别；发生这些情况时须重新核验基准，不能仅凭持久化标记认定旧脉冲仍可用。

## 接口与执行侧

- `POST /api/motion/{side}/home` 和 `POST /api/motion/{side}/return_home_reference` 都必须带显式非空、无重复的 `axes` 数组；旧无参数按钮请求返回 422。
- 返回只检查所选轴的确认、使能、目标限位、位移和最终到位反馈。任何所选旋转轴直接位移超过 180° 时整次拒绝，不按整圈取模；此阈值不代表碰撞安全保证。
- DDS/HAL 保留完整六位轴掩码。寻零和机械参考点返回缺少选择时不再默认启动六轴；空选择在执行侧被拒绝。
- 停止遥操作来源后读取配置，避免完成寻零时把停止前的连接状态重新保存。
- 保留执行侧急停、控制租约和力保护；原生部分启动失败会停止并锁存急停。

## Y 轴 3007 排查结果

日志 `backend/runtime/logs/appstation-m0-20260922_040716.log` 显示，同一个硬件右侧 Card 0 / physical axis 0，在手动负向移动 `deltaPulse=-50000` 时已出现 3007；之后机械参考点返回从 6304 到 5623（差 -681）也被拒绝，绝对/相对两次调用均返回 3007。因此该报错并非只在新增返回接口出现。

本机保存的厂家《DMC5X10 系列运动控制卡用户使用手册》（2025.5，PDF 第 397 页）明确列出：3007 表示负向硬件限位触发，不允许负向启动 pmove。因此可以确认此次 Y 轴负向点位运动被控制卡的硬件限位保护拒绝。[对应系列厂家手册](C:/Users/Administrator/Desktop/平台相关文件/DMC5X10系列控制卡用户使用手册20250710.PDF)

尚未读取出错时的原始限位输入，也未核验传感器、接线和逻辑电平。不能断言限位有效是正常到位还是输入异常。本轮未修改限位配置、未绕过错误、未尝试恢复运动；加按钮不等于解决了 Y 轴的限位问题。
