# 工控机低风险优化迁移指南

核对日期：2026-09-18。用途：供工控机上的开发者或代码助手逐项参考修改，优先选择影响范围小、能独立验证、容易撤回的优化。

**用户已确认：远端代码来自工控机。本次以这份工控机代码为修改基线，从这台电脑的优化中只选取少量低风险增量。** 不要求工控机变成本机的完整 `xie` 版本。

**首批选定 S1、U1、U2 三项：取消后端启动时的自动回工作原点调用、相机调参行允许收缩、数据集三路回放中宽屏列宽修复。** 三项分别形成小补丁，逐项验证。导航、只读列表、订阅等是后续候选，当前不要求实施；整套界面替换、控制租约、HAL、自检、数据契约和停栈策略不放入首批。

**前端整体优化补充见第 6 节**：包括统一视觉、七个业务页面、设置五分区、交互反馈、性能和分批验收。它提供首批之后的完整改版路线，不把整体重构归为低风险，也不要求一次完成。第 11.2 节附有工控机可使用的整体前端优化任务说明。

这里的风险等级评价的是“迁入工控机后产生功能回归、兼容问题及回退困难的可能性与影响”，不是故障概率或实机安全认证。界面变清爽、测试通过和设备控制更安全是不同结论。

### 本轮明确选取的三项

| 独立补丁 | 工控机实际修改位置 | 此轮边界 | 判断完成的依据 |
| --- | --- | --- | --- |

## 4. S0/S1：去除“开机自动回工作原点”

### 4.1 先确认究竟是哪一种回原点

这里的“开机”实际对应 **后端启动事件**，包括 Uvicorn/后端重启，不仅是 Windows 开机。

远端路径：`Start-App.cmd` → `scripts/launch-app.ps1` → `scripts/start-stack.ps1` → 后端 `reconcile_startup_hal_state()`。该函数先清理残留 native teleop，再判断跳过环境变量、配置开关、模式和 HAL 连接，最后可能调用 `commands.home_all()`。配置启用也不等于必然运动，仍受原点、使能、急停等条件约束。

| 行为 | 关键入口/含义 | 本方案处理 |
| --- | --- | --- |
| 后端启动自动回工作原点 | `reconcile_startup_hal_state()` 自动调用 `commands.home_all()` | 只删除这个自动来源 |
| 人工回工作原点 | `/api/motion/home_all`、`/api/motion/{side}/return_origin`，目标是已保存工作原点 | 保留 |
| 机械 homing | `/api/motion/{side}/home` → `motion.home_side` → 控制卡 homing | 保留，不改原点/参考模型 |
| 录制 reset、到位确认 | 录制准备过程的回位和状态判定 | 保留，不因删除启动动作就自动标记到位 |
| 遥操作前回位及运行中原点变化处理 | `teleop.homeBeforeStart`、`pre_home`、原点变化处理 | 保留，属于不同触发路径 |

不要全仓删除带 `home` 的函数。远端部分 teleop connect/录制路径显式传 `pre_home=False`，不能仅凭 `homeBeforeStart=True` 推断所有连接都会回位。

### 4.2 S0：只需暂时关闭时，先用现有入口

在现场确认 `motion.homeOnStartup.enabled` 的保存值。若已经为 `false`，本功能默认分支不会请求回位；仍发生运动时，应根据日志查明是手动、录制 reset、teleop 还是其他调用来源。

使用环境跳过时要注意：远端 `start-stack.ps1`、`start-stack-dds.ps1`、`run-act-deploy.ps1`、`run-act-jepa-deploy.ps1` 会根据 `-SkipStartupHome` 显式写入环境变量的 true/false。因此，全局设置 `APPSTATION_SKIP_STARTUP_HOME=true` 可能被启动脚本覆盖；应核对实际启动命令是否传入该参数。

临时关闭是配置措施，不等于源码入口已删除。通过 UI 保存配置时仍走现场既有保存流程，不能把本机完整配置文件覆盖到工控机。

### 4.3 S1：推荐的最小永久补丁

参考本地 [backend/app.py](../backend/app.py) 的 `reconcile_startup_hal_state()`，在工控机同名函数中只移除启动回工作原点的判断及调用分支。

必须保留：

- 读取启动配置以及必要的生命周期工作。
- `teleop.native.stop` 和 `teleop_mapper.stop("teleop-connect")` 对残留遥操作的清理。
- 人工回位 API、机械 homing、录制 reset、原点有效性检查及现有安全保护。

不要复制本地整个 `app.py`。该文件还含控制租约、停止代际、数据契约、相机 API 等无关差异。S1 本身不改 HAL、DDS、命令协议、力阈值、轴映射或二进制。

第一阶段可以保留旧字段和脚本参数作为兼容项，明确它们不再驱动启动运动；界面可移除该开关或明确标注已停用。不要让操作者以为勾选后仍会执行。待所有调用者核实后，再做下一节的清理。

### 4.4 字段与脚本的完整清理：另作独立补丁

本地已做完整清理，可按需参考：

| 范围 | 清理点 | 工控机需要保留的内容 |
| --- | --- | --- |
| 后端默认与配置 | `backend/core/defaults.py` 删除默认项；`SettingsService.save_config()`、`_merge_defaults()` 删除旧 `homeOnStartup` 键 | 远端 RLock、读取/替换重试、临时读取失败保留配置，以及其他迁移逻辑 |
| 前端 | `frontend/src/types.ts`、`data.ts`、`normalizeConfig()` 和原设置页开关 | 工控机现有 AntD 页面及其余配置字段 |
| 遥操作耦合 | 检查 `app.py`、`teleop_mapping.py` 以及设置页对 `homeOnStartup.mode` 的读取 | `teleop.homeBeforeStart`、工作原点有效性、原有 pre_home 语义 |
| 启动/部署脚本 | 清理四个脚本中的 `SkipStartupHome` 参数、转发和环境赋值 | 其他参数、SDK 路径、力校准、候选二进制和启动顺序 |

删除脚本参数前先检查快捷方式、批处理和外部部署调用者；仍传旧参数时，直接删参可能导致启动失败。完整清理不是首轮取消自动动作的必要前提。

### 4.5 验证与回退

参考 [test_startup_never_moves_with_legacy_home_config](../backend/tests/test_app.py)：用旧配置 `enabled=True`，分别覆盖跳过环境变量未设置、`false`、`true`；三种情况都不得调用 `home_all()`，但旧 teleop 清理仍应调用。

这条本地测试还断言旧配置字段被删除。**只做 S1 时，仅移植“启动不发运动”的测试部分，不要照搬字段删除断言。** 测试直接执行目标 startup 协程，使用临时配置和 mock HAL，不进入完整相机/串口生命周期。

还要保留并验证人工工作原点回位、未使能拒绝、急停拒绝、机械 homing、录制 reset 和 teleop 原点准备的既有行为。源码存在不等于这些实际流程已验收。

回退只恢复本次小补丁。恢复旧自动分支前仍应保持现场开关关闭，并核对启动参数，避免旧配置 `enabled=True` 随回退重新生效。若已经落盘删除字段，代码回退不会自动恢复字段；也不能用旧整份配置覆盖后来更新的标定、原点和设备身份。

## 5. 前端可以独立迁入的优化

### U1：相机调参滑块列允许收缩

参考 [index.css](../frontend/src/index.css) 的 `.camera-tuning-control-row`。当前远端中间列是 `minmax(180px, 1fr)`，本地是 `minmax(0, 1fr)`；优先只摘取允许中间列收缩这一点。

保留工控机现有 `.ant-slider`、`.ant-input-number` 和事件处理。不要整份替换 CSS，也不要用全局 `overflow-x:hidden` 掩盖仍然存在的控件溢出。

验收：800、1024、1440px，浏览器 125%/150% 缩放；输入、滑块和标签不越界，数值仍可读可改，修改前后输入事件与保存请求次数一致。没有复现溢出的分辨率可以只记录，不必为形式统一而改。

### U2：数据集三路回放的中宽屏布局

参考 `index.css` 中 `.dataset-video-grid` 的媒体查询。远端中宽屏三列有 `300/220/220px` 的最小宽度，本地使用可收缩列 `minmax(0,1.2fr)` 与两个 `minmax(0,.8fr)`。

只调整对应断点的布局，保留播放器、数据读取、相机角色和复核操作。使用含三路视频的离线样本，在 760/800/900/1024px 验证视频区及主体无横向溢出、播放控件可见。不能仅凭空数据页截图判定通过。

### U3：顶部模式显示与实际 URL 一致

参考 [AppLayout.tsx](../frontend/src/components/AppLayout.tsx) 的 `workModeRoutes`、`workModeFromLocation` 及 [AppLayout.mode.test.tsx](../frontend/src/components/AppLayout.mode.test.tsx)。

只迁入路由派生和导航映射，保留工控机的 AntD `Segmented`：`/record`、`/auto`、`/settings#manual` 对应其模式，其他页面不误高亮。不要复制同文件中的租约、安全展示或整套 Ui 组件。

验收浏览器前进/后退、侧栏跳转、刷新和带 hash 地址。**模式按钮只导航，不启动录制、策略或运动；相关控制 POST 次数应为 0。**

### U4：只读列表请求失败与旧响应处理

参考 [ModelView.tsx](../frontend/src/views/ModelView.tsx)、[FineTuneView.tsx](../frontend/src/views/FineTuneView.tsx) 的初始读取与 `requestId`，以及 [TaskPages.lifecycle.test.tsx](../frontend/src/views/TaskPages.lifecycle.test.tsx)。

首批只处理 GET：捕获失败、显示可重试错误、卸载后忽略回包、阻止旧列表覆盖新列表。真实模式不能用静态“ready”列表伪装读取成功。保留现场组件库和 API 数据结构。

验收：用可控制返回顺序的 Promise 替身模拟失败、重试、切页与迟到响应；未处理拒绝为 0，每次重试仅一次 GET，旧响应覆盖为 0。

不要顺带移植 Start/Stop/Cancel 或删除操作的防重入；它们改变命令行为，必须单独验证。忽略旧回包只影响界面写回，不能撤回已到达服务端的命令。

### U5：显示组件按所需字段订阅

参考 [frameSelectors.ts](../frontend/src/stores/frameSelectors.ts) 的 `useFrameField`、`numberArrayEqual`，以及 [frameSelectors.test.ts](../frontend/src/stores/frameSelectors.test.ts)、[frameSelectors.live.test.tsx](../frontend/src/stores/frameSelectors.live.test.tsx)。

从单个只读关节/力值显示卡开始，复用工控机现有 Zustand store。不要替换整个 `telemetry.ts`，不改变 WS 接收、丢帧策略、心跳、锁存判定或后端采样频率。

验收：完成初始挂载后，mock 连续提交 100 次无关字段变化，目标组件新增 render 应为 0；相关字段变化时必须更新。显示 freshness、过期或告警的组件还须覆盖时间戳/时钟驱动，不能只比较数值。

相机比较要覆盖实际显示的 `health`、`timestampSkewMs`、`frameAgeMs`、`label`、`fps`、`backend` 等字段；避免通过漏比较来“减少重渲染”。先做展示卡，PreCheck、急停、使能等决策组件后评估。

### U6：少量页面使用懒加载

参考 [App.tsx](../frontend/src/App.tsx) 的 `React.lazy` 和每条路由的 `Suspense`。可以先对 Dataset、Model、FineTune 等页面做按需加载，保留工控机的 ConfigProvider、AntD、ECharts、根连接 effect 和既有构建依赖。

验收：冷启动未访问的页面分块不提前请求，访问后正确加载，原 URL 刷新可打开；模拟 chunk 404/加载失败时，导航和全局急停入口仍挂载。检查重复进入页面没有新增重复 WS 或控制请求。

本地 [RouteErrorBoundary](../frontend/src/components/RouteErrorBoundary.tsx)、[ModuleErrorBoundary](../frontend/src/components/ModuleErrorBoundary.tsx) 会调用 `revokeControlLease`，不是纯视觉组件，不能直接抄入缺少对应协议的工控机。失败处理要符合工控机当前控制故障策略；无法独立适配时，先保留该路由的原有加载方式。

统计同环境实际首屏 JS 传输总量和加载耗时，不只看入口 JS 文件大小。按需分包不能直接证明 CPU、内存或物理控制延迟改善。

### U7：非活动设置面板卸载，留到后批次

工控机参考版本主要是 config/manual 两个 Tab，本地已拆成五个 Tab。五 Tab 重构不能当成小补丁整体复制。

可先独立拆分纯显示区域，再让局部定时器和预览随面板卸载释放。参考 [SettingsView.tsx](../frontend/src/views/SettingsView.tsx)、[ManualControlPanel.tsx](../frontend/src/views/settings/ManualControlPanel.tsx) 及 [SettingsView.regressions.test.tsx](../frontend/src/views/SettingsView.regressions.test.tsx)。

验收：面板往返 20 次不增加监听器/定时器；离开视觉面板后没有该面板新增的流请求；返回后正常恢复；未保存编辑、选中配置及请求 pending/互斥仍正确。**不能把命令锁放到会卸载的卡片内，导致切 Tab 后重复下发。**

减少页面预览不等于关闭摄像头，也不能停止录制器仍需使用的采集。当前没有现成的视口级暂停实现可直接迁移。

## 6. 前端界面整体优化：目标、范围与分阶段迁移

本节说明“工控机界面可以逐步优化成什么样、需要保留什么功能、哪些部分不能直接照搬”。本机已实现的页面组织和样式可以参考，但工控机现有功能仍是验收基线。历史总结中的“修改前”不是本次远端基线；下表列出的是可参考的组织方式，不宣称每一项都是工控机缺少的新功能。

本节相对源码链接用于定位文件，会打开工作区版本。核对固定参考内容时，应通过第 1 节的 GitHub 固定版本入口，或使用 `git show 21054a7:frontend/src/对应路径` 读取；不要把工作区后续修改直接当作本节的参考实现。

### 6.1 推荐方式：先统一外观，再调整结构与加载

工控机可以保留 AntD、ECharts 和当前控制接口，先迁入本机的视觉规则、卡片组织和导航改进。这能覆盖整体改版中容易感知的部分，同时把组件替换的兼容问题留到后续处理。

| 层次 | 本机固定版本的实现 | 工控机推荐做法 | 风险 |
| --- | --- | --- | --- |
| 视觉层 | CSS token、浅色工作区、白色卡片、状态色、统一数字与控件样式 | 在现有组件上逐页应用主题和局部样式 | 局部低；全局主题较低至中 |
| 页面组织 | 固定壳层、七个业务路由、设置五分区、状态卡和操作区分组 | 先调整阅读顺序和导航，再拆分大页面 | 较低至中；拆分设置页为中 |
| 交互反馈 | loading/disabled、请求错误、录制阶段派生、部分异步失效处理 | 保留现场请求和状态机，仅优化已有状态的表达 | 只读展示较低；控制反馈需单独核对 |
| 显示性能 | 按字段订阅、路由懒加载、活动面板挂载、Canvas 曲线 | 按 U5/U6/U7 逐项处理，图表替换最后评估 | 较低至中；完整替换为中至高 |
| 依赖替换 | 自有 `ui.tsx`，移除 AntD 与 ECharts 直接依赖 | 独立批次；并非获得统一外观的前提 | 中至高 |

纯主题、布局和加载调整无需 HAL 重建。涉及新状态字段、控制门槛或新 API 时，不再按纯前端样式任务处理。

### 6.2 统一视觉与响应式布局

参考 [index.css](../frontend/src/index.css) 的 `:root`、壳层、卡片、表单及媒体查询。以下数值来自本机固定版本，可用作主题参考，不要求工控机逐字复制全部 CSS。

| 范围 | 本机参考 | 工控机迁入要求 |
| --- | --- | --- |
| 背景与层级 | 工作区 `#EEF1F5`，卡片白色，次级区域 `#F6F8FB` | 用背景、标题和留白区分分区，保留日志与关键状态的可读性 |
| 操作与状态 | 操作蓝 `#1B6CF3`；正常绿 `#0D9B6C`；警告橙 `#D4870F`；危险红 `#E03A4F` | 状态同时配文字，不只靠颜色；“未知/断连/等待确认”不能装饰成正常状态 |
| 卡片与控件 | 圆角 token 为 6/10/14px，边框 `#D9E0E8`，轻量阴影 | 先在非控制卡片验证，再统一表单；不以缩小急停、停止或数字输入的点击区域来压缩布局 |
| 数字与单位 | 等宽数字 `tabular-nums`，标签、数值、单位分层 | 长数值、负号、小数和错误文本不截断；单位与数据换算逐项核对 |
| 表单 | 标签、弹性输入区域与数值区域对齐，`min-width:0`、可收缩 Grid 列 | U1/U2 为第一批；其余表单逐个检查，不用全局隐藏溢出掩盖问题 |
| 页面滚动 | 主内容区承担页面滚动，局部列表/日志可独立滚动 | 小屏能滚到全部设置和确认按钮，保持全局停止入口可访问 |
| 焦点与动效 | 按钮/输入框可见焦点，部分过渡，`prefers-reduced-motion` 样式 | 检查键盘操作及系统减少动画偏好；保留工控机已有交互能力 |

布局应随宽度换列、换行和堆叠，不用整页 `transform:scale()` 或统一缩小字体来适配工控机。全局主题会影响所有弹窗、表单与覆盖层，需要跨页验收；“只改 CSS”不等于没有回归风险。

### 6.4 设置页整体分区与功能保留清单

参考 [SettingsView.tsx](../frontend/src/views/SettingsView.tsx) 及 `frontend/src/views/settings/`。本机分区可以移植到现有 AntD Tabs；不需要同时换成自有 Tabs。

| 分区 | 本机组织方式 | 工控机不能遗漏的能力 |
| --- | --- | --- |
| 系统连接 | HAL、数据存储 | HAL/WS 配置、连接与诊断、数据目录、录制 FPS、完整配置应用、全局快照恢复/删除等既有入口 |
| 安全与力觉 | 安全链、左右六维力卡 | 现场急停/复位条件、HKVL 主用与 NI-DAQ 手动备用、通道/串口和标定；工控机已有双阶段 Tare、校准状态与能力检查不得被本机旧参考覆盖 |
| 运动控制 | 手动面板、左右运动卡 | 使能及未知反馈、停止、速度/步长/限位、工作原点捕捉/恢复/清除、人工回位、机械 homing、运动快照；按 S1 处理启动自动回位入口 |
| 遥操作 | Omega.7 主手、夹爪 | 每只主手的在线与逻辑连接状态、目标臂映射、原点准备、夹爪绑定与控制来源；不得新增自动连接或自动使能 |
| 视觉 | PICO、全局及双腕相机 | 相机识别/绑定、曝光与增益、预览、相机角色、PICO 状态和控制；录制中设备操作限制保持原样 |

拆分前建立“旧控件 → 新分区 → 原处理函数/API”的清单。先移动布局并保持原有挂载与状态，再单独评估非活动面板卸载（U7）；两项不要混为一个纯样式补丁。

hash 路由也要保持：`#manual`、左右运动/力觉/主手入口及 PICO 跳转都应选中并显示正确分区。本机 PICO `#teleop` 与主手 `#teleop-left/right` 含义不同，不要按字面把所有 teleop hash 都放入同一个 Tab。

### 6.5 统一交互反馈，但保留原命令语义

| 场景 | 前端优化要求 | 迁移边界 |
| --- | --- | --- |
| 读取列表/详情 | 明确加载、空数据、失败和重试，忽略过期响应 | U4 可独立处理；真实读取失败不能退回演示“正常”列表 |
| 保存/应用配置 | 区分未保存、提交中、被拒绝、已保存与设备应用结果，错误就近展示 | 不能把 HAL 重连成功写成配置已应用；保留当前请求锁和完整 payload |
| 设备动作 | 显示等待、拒绝、失败、反馈未知等当前已有状态 | HTTP 接受不等于设备完成；不照搬本机使能状态机或新增自动重试；停止入口不被普通 loading 覆盖 |
| 录制进度 | 阶段、进度条、计时、保存中及质量报告保持一致 | 可以参考 `recordDisplay.ts`，但需匹配工控机已有 phase；不能只复制新 phase 字符串而漏掉后端同步 |
| 重要确认 | 保留前后值对比、取消和确认；长内容可滚动且能访问按钮 | 不因弹窗改版省略覆盖原点、应用快照、删除等现有确认 |
| 键盘与辅助信息 | 可见焦点、输入标签、图标按钮名称、进度语义、对话框焦点进入/返回 | 这些是验收要求，不代表本机自有控件已完整实现；先保留成熟组件已有行为 |

本机 [ui.tsx](../frontend/src/components/ui.tsx) 具有原生 disabled/loading 处理等实现，但不能仅凭相近 props 名称认为与 AntD 等价。替换时特别检查空数值、min/max/step、下拉选项、键盘 Tabs、Tooltip、Modal 焦点与 Escape、表单提交以及表格/分页行为。

### 6.6 整体改版的四个阶段

这四个阶段是首批 S1/U1/U2 之后的候选路线；每阶段仍按页面拆小补丁，不一次覆盖整个 `frontend/`。

| 阶段 | 建议实施内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| V1：统一外观与导航 | 保留 AntD/ECharts；统一主题、卡片层级、表单对齐与状态文字；先做总览和非控制列表，再做录制/自动页面外观；纳入 U3 | 七页主要状态可显示，导航正确，原控件功能保留，无新增控制请求；页面和弹窗缩放验收通过 |
| V2：整理页面结构与异步显示 | 设置五分区、硬件卡拆分、hash 直达、U4 读取错误处理；表单和请求状态保留后再考虑 U7 | 控件对照表无遗漏，切页不丢编辑和在途约束，原点/快照/校准/录制相关离线回归通过 |
| V3：优化加载与显示更新 | 按 U5/U6 从只读卡片和非控制路由开始；逐项记录 render、分块请求与清理情况 | 相关字段、过期和告警仍及时更新，加载失败可恢复，没有新增 WS/监听器/定时器泄漏 |
| V4：选择性替换依赖 | 确有包体或维护需求时再评估自有 UI、Canvas；先替换非控制组件/单张图，保留原图表可回退版本 | 组件行为和图表能力逐项对齐，包体有同条件前后证据，未失去实际需要的功能；无需替换时停在 V3 |

本机 `package.json`、lockfile、`vite.config.ts` 含整轮改版和工具链变化，不能为一个视觉补丁整份复制。保留工控机现有锁文件；若单独引入确需的组件或图标，记录必要依赖，不顺带升级框架、构建器或测试工具。

### 6.7 已核实的本机展示局限：避免照搬后造成误解

| 位置 | 固定提交 `21054a7` 中的事实 | 工控机处理原则 |
| --- | --- | --- |
| Auto 运行信息 | “推理延迟”来自 `88 + Math.sin(elapsedSec) * 9`，“控制频率”写为 30Hz | 不能迁入为实测指标；保留现场真实指标，无对应数据时明确未接入/不可用 |
| Auto 配置控件 | 算法、同步/异步及任务文本是页面本地状态，没有随这些控件接入完整后端参数提交链 | 不能因为选择框变化就提示后端策略已切换；接口接入另作功能任务 |
| Model 精度与导入 | 精度存于 `precisionByModel`，启动只传 modelId；导入按钮传固定 `local_checkpoint` | 保留工控机已有真实功能，不能把这些演示性控件当作可直接迁入的量化切换或文件导入 |
| 部分状态和按钮 | 总览 PICO 卡固定显示待连接；力数据导出和运动卡“手动自检”按钮仅写操作日志 | 不描述成实时诊断、已导出文件或已完成自检；以工控机实际接口和反馈保留功能，不与工作区后续自检改动混淆 |
| 力值标题与图表 | 部分 HKVL 标题写 N，而明细/合力仍按 ×1000 显示 mN；Canvas ForceChart 六通道共用 mN 标注 | 必须核对每项实际缩放及力/力矩单位；不能仅改标题或把六维量都标为 mN，也不能再次交换左右侧 |
| Canvas 曲线 | 本地 `LiveLineChart` 绘制曲线和静态图例；远端 ECharts 有 tooltip、时间轴数据及图例交互 | 不是功能等价替换；现场若需悬停读数、真实时间定位或图例筛选，保留 ECharts，或补齐并验证后再换 |

这些是源码检查得出的限制，不是本次发现后已经修复的项目。整体界面迁移应复制已核实的布局思路，逐项保留真实业务能力。

### 6.8 整体前端验收与回退

## 7. 哪些内容不宜列为首轮“低风险优化”

| 内容 | 为什么需要单独设计和验证 |
| --- | --- |
| 移除 AntD、整体更换 Ui、Canvas 替换 ECharts | 涉及表单、焦点、disabled/loading、弹窗、图表及大量样式；本地迁移过程中曾补回遗漏功能，不是简单减依赖 |
| 整份替换 API/store、请求超时、使能状态机 | 本地实现包含会话所有权、结果未知、停止代际、队列和后续确认；不是只加 timeout |
| 浏览器租约、失联停机、DDS deadline、HAL ACK/原子锁存 | 前端、后端、native DDS 和 HAL 必须匹配；不能只更新一端，也不能关闭检查来兼容 |
| 本地 400ms 隐藏页面显示节流 | 与紧急状态提交和连接处理相邻；不能让心跳、停机、锁存或执行侧处理一起降频 |
| 双阶段 Tare、自检/校准 capability | 工控机远端已有、本地未完整迁入；覆盖会造成能力回退或前后端不配套 |
| 数据契约、左右转换、旧集迁移、原点归一化 | 远端已有主体实现；再次变更会影响已有数据和外部模型，代码回退不等于数据回退 |
| 相机驱动、USB 身份、运行中曝光、录制忙保护 | 涉及设备属性和共享采集生命周期；先复现具体问题，再移植相关 driver/API/config/UI 片段并验证 |
| 开页/关页自动停栈、无客户端超时停栈 | 会改变录制、刷新、多入口和异常退出行为；不是本次显示优化的附带功能 |
| SDK/驱动/依赖的大版本升级、串口及标定默认覆盖 | 增加独立变量，难以判断回归来自代码还是运行环境 |

本地相机值得后续按缺陷单独参考的增量：已打开 direct capture 切回 Auto 的曝光优先级补漏、稳定身份不被旧配置迁移覆盖、绑定成功后避免第二次整配置 PUT、录制启动/收尾期间禁止识别绑定。这些不属于纯 UI 优化，也不承诺现场稳定 30 FPS。

### 第一步：记录现场基线

先在工控机项目根目录进行只读确认，例如：

```powershell
git status --short
git branch --show-current
```

保存独立的源码差异和本地配置备份，包括被 Git 忽略的 runtime、工作原点备份及必要部署文件。Git 分支不能备份忽略文件；含设备配置、凭据的备份留在工控机，不上传 GitHub。

### 第二步：逐项修改，不整包覆盖

从工控机自己的当前版本创建工作分支，保留已有改动；先实施 S1、U1、U2 中确有需要的项目，各用一个独立补丁/提交。需要从 GitHub 获取参考时，先确认 remote 实际指向 `ccoxo/E2EAPP_MicroMani`；remote 名称不一定叫 `ccoxo`。

本轮不要求增加本地全部安全协议，不要求切换为本机 UI 框架，也不改现场数据和默认硬件映射。每个补丁说明“改了哪个触发点、原功能哪些仍保留、如何验证和回退”。

### 第三步：先离线验证，再安排现场切换

下列是验证入口示例；先把对应小测试适配到工控机代码，再执行，不能因同名文件不存在就整份导入本机测试和源码。

| 修改范围 | 最小验证 |
| --- | --- |
| S1 启动自动回位 | 定向 startup 协程测试；旧 enabled=True + 三种环境值不发运动，清理旧 teleop 仍执行；人工回位/急停拒绝/录制 reset 的 mock 回归 |
| U1/U2 CSS | 前端生产 build；带数据/视频替身的受影响宽度与缩放检查；按钮、表单操作和请求次数不变 |
| U3 导航 | 适配 `AppLayout.mode.test.tsx`；前进后退、直达 URL、非模式页面不误高亮、控制 POST 为 0 |
| U4 只读列表 | 适配 `TaskPages.lifecycle.test.tsx` 的读取用例；失败、乱序、卸载、重试 |
| U5 selector | `frameSelectors.test.ts` 与对应组件 live 测试；相关字段更新、无关字段不 render、过期/告警更新 |
| U6/U7 生命周期 | 页面加载失败、面板反复进入退出、连接和定时器清理、在途命令锁/编辑值保留 |

前端源码变更后用工控机现有依赖锁运行类型检查及 build，例如 `npm --prefix frontend run build`。先保留依赖版本，不顺手升级。不要直接编辑 `frontend/dist/`；需要实际切换前端时，成套替换 `index.html` 和对应 assets，避免新旧 chunk 混用，并保留上一套完整产物。

后端使用工控机已有项目虚拟环境，测试用临时目录、fake HAL 和设备替身。单独设置 `APPSTATION_HAL_MODE=test` 不保证所有相机/串口都被屏蔽；也不要在未隔离接口时直接运行浏览器视觉脚本，它可能连接正在运行的真实后端。

现场验证安排在没有录制/运动任务的维护窗口，确认实际运行的进程加载了新版本。S1 的现场目标是“后端启动不自动请求回位、状态可读取、人工操作入口保留”；任何真实运动验收按现场授权和操作流程执行，不由本指南自动发起。

### 第四步：异常时只回退当前批次

- 保留上一套前端完整产物、后端小补丁与运行配置备份；不要在验证中自动重写配置或更新 HAL。
- 一个补丁一份撤回记录；已提交的独立功能可在确认工作区状态后用对应 revert，未提交的改动按保存 diff 逐项撤回。
- 不使用 `git reset --hard` 或整目录覆盖清除其他人的改动。
- S1 回退注意旧开关重新生效；前端回退成套恢复旧 HTML/assets。数据契约和已录制数据不包含在首轮回退范围内。

## 9. 如何判断优化确有收益

| 目标 | 建议记录 | 通过口径 |
| --- | --- | --- |
| 启动行为 | 旧配置启用情况下的 mock 调用轨迹、现场启动日志 | 无启动自动回位请求，既有清理及人工入口保留；不能仅凭“设备没动”判断已删除调用 |
| 布局可用性 | 实际工控机分辨率/缩放，以及受影响的窄窗口截图 | 控件、视频和关键按钮不越界、不被遮住，参数读写行为不变 |
| 渲染开销 | 相同模拟遥测下组件 render 次数、React Profiler 记录 | 无关更新减少，相关数据显示及过期/告警没有冻结 |
| 页面加载 | 同浏览器、同缓存条件、同数据下的分块请求与首屏总传输量 | 未访问页面延迟加载，失败可恢复，导航/停止入口仍可见 |
| 长时间切页 | 往返 20 次前后监听器/定时器/页面流请求数量 | 不持续增长；在途动作不重复、不因卸载丢失互斥 |

这里是迁移后的验收建议，不是已在工控机测得的结果。本地历史记录能证明部分源码路径和离线行为，不能换算为“CPU 降低多少百分比”或“物理停机更快”。
