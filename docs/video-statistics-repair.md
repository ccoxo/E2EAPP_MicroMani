# 图像统计与保存尾帧修复

## 问题与处理位置

安装版本的 LeRobot 视频统计对 uint8 像素直接平方，发生溢出，使单段图像标准差错误地成为 0。采集端在独立编码进程中将统计输入转换为 float64，避免后续数据重复出现问题；不修改安装包。

历史数据可以从保存的 MP4 重算统计，不需要重新采集。统计来自解码后的 RGB 像素，与压缩前像素可能略有差异。工具遍历全部帧，沿用 LeRobot 空间下采样，使用直方图计算均值、标准差和分位数。仅更新副本中的图像统计，保留视频、数值标签和其他统计。

```powershell
backend/.venv/Scripts/python.exe scripts/recompute_video_statistics.py 'E:\data group\micro_assembly_v5' 'E:\data group\micro_assembly_v5_stats_fixed'
```

输出目录必须尚不存在。工具先校验各段视频帧数，再复制并写入统计，不覆盖原数据集。

正常保存 episode 时，设备停止前保存动作状态快照，待写入尾帧使用该快照，防止读取停止后的夹爪复位目标。保持先停止设备再排空录制队列的顺序；此修复不等于验证了所有异常中断路径。

## 2026-09-18 验证

- 数据集共 5 段、4105 帧；修复副本的 15 个视频和 5 个数值文件 SHA-256 与原文件一致，非图像统计及其余 episode 元数据一致。
- 第 1 段（从 0 编号）的 frame_index=822、全局 index=1811、27.4 秒处的 action[6] 可疑，原始标签保留。副本 `meta/quality_review.json` 建议训练前排除该帧；这是审查标记，训练加载器不会自动应用，序列采样也应避开包含该帧的窗口。
- 本轮按用户要求不处理力数据；单侧操作导致另一侧状态保持不变属于实验设计。
- 录制与编码相关测试 94 项通过；相机时间戳、录制诊断和预览卡顿测试 16 项通过。
- 离线三路 640×480、30 FPS 持续 45 秒：每路 1350 帧，无编码丢帧，队列峰值 0/0/1，三路送帧耗时 P99 6.31 ms，调度迟到 P99 1.07 ms。离线结果不能代替下一次实机采集验收。

代码需要重启后端后生效；已有数据使用修复副本。当前没有自动过滤可疑动作标签，也没有通过插值伪造其真实目标。
