# 数据集续录条件检查

继续向已有 native 数据集录制时，后端在启动写线程前检查一次，在写线程打开数据集前再次检查。拒绝时返回具体原因，不启动本次录制，也不覆盖已有数据集元数据。

## 检查内容

- 两份元数据的数据契约、录制帧率、字段类型、形状及通道顺序。
- 参与臂和夹爪保持一致。工作原点 W 必须有效且为有限数值，参与硬件侧各轴差值不超过 0.5 pulse；操作者侧通过现有映射转换成硬件侧。
- 三个相机角色的稳定身份、配置采集帧率、采集及保存分辨率。设备重新枚举导致序号或标签变化、仅预览分辨率变化可以接受。
- 运动轴顺序、单位和参与硬件侧的脉冲换算标定。
- 元数据计数、会话历史和片段清单的结构。读取 native 片段索引，按 `datasetFromIndex/datasetToIndex` 和帧数关联，不能假定历史软件编号等于原生编号。范围不符、重复关联或没有保留/弃用记录的原生片段会阻止续录，提示核查历史或使用整理后的副本。

新目录可以正常创建。明确为零帧、零片段且没有片段文件或清单记录的空集，可建立第一次实际采集条件；旧的基本契约检查仍适用。仅含丢弃片段的目录，按已有采集条件检查。

旧数据集缺少参与侧字段时，只有片段清单每条都有参与侧且全部一致，才采用该记录。其他无法证明兼容的旧数据不猜测、不自动迁移，使用新数据集或另行核查。

## 历史追溯

有片段记录后，保留数据集最初的 `sessionOrigin`、`hardware`、`recording` 和参与侧。每个新会话在 `sessionHistory` 中增加一次快照，含会话编号、开始时间、首个片段序号和当次配置；新片段的 `session` 字段关联该快照。每个片段原有的力标定快照仍独立保存。

已保存后丢弃只标记 `deleted=true, status=invalid`，保留原始数据和附加记录。软件编号不再退回，重录使用新编号。前端等待丢弃成功才进入复位等待；失败保留质量报告，可重试。保存拒绝覆盖已存在的同编号记录。

## 生成排除弃用片段的训练副本

`scripts/export_retained_dataset.py SOURCE DESTINATION` 默认只读核对并列出保留/排除的原生索引。输出目录必须是尚不存在、与原集分离的目录；加 `--apply` 才生成新集。工具使用当前环境的 LeRobot 数据集编辑 API，同步重排数据、视频和片段元信息，保留完整数据契约以及每条记录的来源帧范围。

对于历史编号复用造成的弃用记录覆盖，不能把没有记录的原生片段直接判为弃用。必须另提供经过日志核实的原生弃用索引 JSON 数组：`--discarded-indices-file PATH`。该列表不得与明确保留的记录冲突。工具导出后逐片段核对数值列与帧顺序，核对原集全部文件 SHA256 不变，报告写入新集的 `meta/retained_export_report.json`。原集写入在导出进程中被拒绝。

导出只排除明确删除/无效/弃用片段，不等同于质量验收。使用原始 LeRobot 数据目录训练的外部程序不保证自动读取软件的删除标记，应使用整理后的副本或经过帧范围核对的原生索引清单。

## 使用边界

- 比较的是记录与配置，不能检测相机被物理挪动、工件或场景变化，仍需人工保持一致。
- 不完整扫描或修复 parquet、视频内容，不保证断电时文件写入原子性。
- 拒绝续录后按提示恢复原条件，或创建新数据集；不要修改旧元数据伪装兼容。
- 离线测试使用临时目录和设备替身，覆盖兼容续录、拒绝路径、旧元数据保护与会话追溯；不代表已完成工控机真实相机、DDS 或采集验收。
